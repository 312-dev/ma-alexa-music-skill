This is the ADMIN_TOKEN you set when you deployed the bridge. It is not something Ampere generated for you, and it is not your Amazon password.

Where do I find it?

Wherever you put it when you started the container. In rough order of how most people run this:

An env file

grep ADMIN_TOKEN .env

Docker or Compose, reading it back out of the running container:

docker exec {{ container_hint }} printenv ADMIN_TOKEN

Nomad, if the value came from a variable:

nomad var get -item=ADMIN_TOKEN nomad/jobs/<job-name>

Kubernetes:

kubectl get secret <name> -o jsonpath='{.data.ADMIN_TOKEN}' | base64 -d

Run these in a terminal you control. Anything that prints a secret into a chat window, a CI log or a shared session has leaked it.

I never set one, or I have lost it

Set ADMIN_TOKEN in the environment and restart the bridge. Any long random string will do: 

openssl rand -hex 32

Changing it signs out every existing session, because the cookie carries a digest of the token rather than the token itself. That is also how you revoke access if you think it has leaked.

With no token set at all these pages refuse to serve rather than serving open, so an empty value is not a way in.

Why a form and not a header: browsers cannot attach X-Admin-Token to a normal navigation, so signing in here sets a signed cookie instead. The same token gates /diag and /captures.
